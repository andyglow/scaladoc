    The model

    The map is not the territory.

    — Alfred Korzybski

    A parsed comment is a map of the comment, and like every map it leaves things out on purpose. The border is gone, and so are the exact spaces and how a list item was indented. What remains is what the comment says: which tags it has, and how its text is structured. This page is the legend of that map.

    Scaladoc and its tags

    A Scaladoc is a list of tags, in the order they appear. The description, the text before the first tag, is a tag too. Most tags hold their text as Markup. A few, like @author or @since, hold plain strings, and some, like @documentable, hold nothing. The syntax page has the full list.

    Tag      = Description       (Markup)
         | Constructor       (Markup)
         | Param             (String Markup)
         | TypeParam         (String Markup)
         | Returns           (Markup)
         | Throws            (String Markup)
         | See | Note | Example | UseCase | Todo | Deprecated | Migration   (Markup)
         | Author | Version | Since                                       (String)
         | Group             (String)
         | GroupName         (String String)
         | GroupDescription  (String Markup)
         | GroupPriority     (String Int)
         | Documentable
         | InheritDoc
         | OtherTag          (String Markup)

Scaladoc = List Tag

    Markup

    Markup comes in two kinds: blocks, which stack on top of each other, and spans, which run inline within a block. A Document holds blocks, and a tag’s text is always a Document. The nodes are named for what the markup means, not how it’s written, so '''bold''' in wiki syntax and **bold** in Markdown are both Bold. A few only come from Markdown, since the wiki syntax has no way to write them; they’re marked below.

    Span     = PlainText   (String)
         | Monospace   (String)
         | Italic      (List Span)
         | Bold        (List Span)
         | Underline   (List Span)
         | Superscript (List Span)
         | Subscript   (List Span)
         | Strikethrough     (List Span)           -- Markdown
         | Link        (String (List Span))        -- target, title
         | Image       (String String)             -- Markdown: source, alternative text
         | LineBreak                               -- Markdown: a hard line break
         | Checkbox    (Boolean)                   -- Markdown: a task list item's, at its start
         | FootnoteReference (String)              -- Markdown: a footnote's label
         | HtmlTag     (String)                    -- an HTML tag the model has no node for

Markup   = Span
         | Paragraph     (List Span)
         | Heading       (Level (List Span))       -- Level: One to Six
         | CodeBlock     (String (Option String))  -- code, the language a Markdown fence names
         | BlockQuote    (Document)                -- Markdown
         | UnorderedList (List Document)           -- each item: its text and nested lists
         | OrderedList   (List Document Style)     -- Style: Decimal, LowerRoman, UpperRoman, LowerAlpha, UpperAlpha
         | Table         (Row (List Alignment) (List Row))   -- a Row: one Paragraph a cell
         | HorizontalRule
         | Footnote      (String Document)         -- Markdown: label, text
         | Document      (List Markup)

    The spans that hold other spans can nest without limit, so walking the model is naturally recursive. Here is a function that collects every link target in a piece of markup, however deep it sits:

    def links(m: Markup): List[String] = m match {
  case Link(target, title)     => target :: title.flatMap(links)
  case Document(elements)      => elements.flatMap(links)
  case Paragraph(spans)        => spans.flatMap(links)
  case Heading(_, spans)       => spans.flatMap(links)
  case x: HasSpans             => x.spans.flatMap(links)
  case x: ListBlock            => x.items.flatMap(links)
  case Table(header, _, rows)  => (header :: rows).flatMap(_.cells).flatMap(links)
  case BlockQuote(content)     => links(content)
  case Footnote(_, content)    => links(content)
  case _                       => Nil
}

Scaladoc.fromString(
  """/** See [[scala.Option]].
    |  *
    |  *   - '''also [[scala.Either]]'''
    |  */""".stripMargin).map(_.descriptions.flatMap(links))
// res0: Either[ScaladocException, Seq[String]] = Right(
//   value = List("scala.Option", "scala.Either")
// )

    Building markup by hand is just as direct. Every span has a shorthand for the common case of a single piece of text:

    Paragraph(PlainText("Use "), Bold("this"), PlainText(" or "), Link("scala.Option"))
// res1: Paragraph = Paragraph(
//   markup = List(
//     PlainText(value = "Use "),
//     Bold(spans = List(PlainText(value = "this"))),
//     PlainText(value = " or "),
//     Link(target = "scala.Option", title = List())
//   )
// )

    Text, when markup is too much

    Omit needless words.

    — William Strunk Jr., The Elements of Style

    Many tools want a string, not a tree: a schema needs a description, a log line needs a message. Two methods give one. plainString writes the markup back in wiki syntax, and trimmed tidies the whitespace first, which is usually what you want:

    val m = Scaladoc.fromString("/** A   ''nice''\n  *   description. */").map(_.descriptions.head)
// m: Either[ScaladocException, Markup] = Right(
//   value = Document(
//     elements = List(
//       Paragraph(
//         markup = List(
//           PlainText(value = "A   "),
//           Italic(spans = List(PlainText(value = "nice"))),
//           PlainText(
//             value = """
//   description."""
//           )
//         )
//       )
//     )
//   )
// )

m.map(_.plainString)
// res2: Either[ScaladocException, String] = Right(
//   value = """A   ''nice''
//   description."""
// )
m.map(_.trimmed.plainString)
// res3: Either[ScaladocException, String] = Right(
//   value = "A ''nice'' description."
// )

    Scaladoc has helpers for the parts that tools ask for most. Each comes in two flavors: one that returns the markup, and a text one that returns it as trimmed plain text.

    Markup Text What
    descriptions textDescriptions the description
    params textParams @params by name
    typeParams textTypeParams @tparams by name
    throws textThrows @throws by exception type
    returns textReturns @return
    summary textSummary the first sentence, as scaladoc shows it in member lists

    The summary is the description’s first paragraph up to and with its first full stop, the one followed by a space or the end. A @shortDescription tag replaces it:

    Scaladoc.fromString(
  """/** Keeps the users of the app. All of them,
    |  * in one place.
    |  */""".stripMargin).map(_.textSummary)
// res4: Either[ScaladocException, Option[String]] = Right(
//   value = Some(value = "Keeps the users of the app.")
// )
